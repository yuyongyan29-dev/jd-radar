# 评分规则(排序引擎)

> 定位:分数是**排序工具**,不是报告门面。它让 /compare 和 /batch 能用同一把尺子排优先级;决策卡上呈现的是判断与行动,分数收在折叠区。

## 维度与默认权重

| 维度 | 默认权重 | 说明 |
|---|---|---|
| 方向匹配 | 25% | 岗位的真实方向(拆掉包装后)与用户目标方向的吻合度 |
| 技能匹配 | 25% | JD 真实要求(非装饰性要求)与用户技能/经历的吻合度 |
| 年限资历 | 15% | JD 要求区间与用户实际年限的关系(超出或不足都扣) |
| 薪资 | 15% | 相对用户三档(理想/满意/底线)的位置;按到手口径换算,14 薪以下结构按用户敏感度修正 |
| 工作制 | 10% | 双休/大小周/单休、下班时间,按用户容忍度计 |
| 通勤 | 10% | 相对用户上限的余量 |

**权重用户可调**:/setup 时询问是否调整;`profile/profile.yaml` 的 `weights:` 字段生效。默认值经 8 场景试算验证(见 `evals/weight_calibration.py`):方向权重必须 ≥ 技能权重,否则会给"技能匹配但方向错位"的岗位过高排序——对转方向求职者是灾难性误导;均权与技能极重两种方案均在试算中出现排序颠倒。

## 计分规则

1. 每维 0-10 打分,**每个分数必须给出可反驳的理由并引用原文**(标注信源级别)。
2. 总分 = 已知维度加权平均(权重归一化)。
3. **未知维度绝不猜**:不参与计分,单独报「信息完整度」= 已知维度权重和 / 总权重。
4. **波动区间**:未知维度分别按 0 分与 10 分代入,给出区间,如「排序分 7.7(完整度 90%,区间 6.9~7.9)」。
5. **同档规则**:两岗分差 < 0.15 视为同档,对比表中并列呈现,不制造虚假区分度。

## 冲突与标记(不进分数,进决策卡)

- **红线冲突**(用户声明的红线被命中,信源 ≥ L2 时确认):置顶警示「与你声明的红线 X 冲突」,该岗位在排序中降入"冲突组"单独列出。工具**永不说"不投"**,决定权在人。
- **资格风险**(JD 硬性要求与档案不符,如年限/学历):判断层明示「JD 要求 X,你的档案是 Y,存在被筛风险」,并给出是否仍值得尝试的依据(如 JD 其他信号显示要求可谈)。
- **疑似不合理限制**(35 岁上限、第一学历、性别、婚育等):标注「疑似就业歧视性限制」,提示被筛风险与用户的选择空间,**绝不**将其内化为对用户的否定,也不自动降低排序分。

## 决策带(仅辅助排序展示)

≥8.5 优先沟通 · 7.0~8.4 值得聊 · 5.0~6.9 匹配一般 · <5.0 与画像明显错位。决策带只描述匹配度,不替用户做投/不投的决定。

**完整度优先规则:信息完整度 < 70% 时,无论分数多高,决策带一律显示「信息不足,先补关键信息」**——防止"高分+低完整度"被扫一眼当成确信高分岗;分数与区间照常在折叠区展示。
