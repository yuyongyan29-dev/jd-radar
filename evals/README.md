# Evals:让「分析准不准」变成有数字的问题

本目录是 jd-radar 与所有同类项目拉开差距的地方:每次修改评分规则或提示词,都要重跑标注集,结果记入 CHANGELOG。

## 结构

- `golden-set/` — 标注样本。每个样本 = JD 原文 + 画像(persona)+ 人工判断(该画像下的正确结论与理由)。目标 30~50 个,覆盖:正常岗、坑岗(培训贷/外包壳/幽灵岗)、歧视性条款岗、信息残缺岗。
- `weight_calibration.py` — 权重默认值试算(8 场景 × 3 权重方案),运行 `python3 evals/weight_calibration.py`。
- `CHANGELOG.md` — 每轮迭代的指标变化。

## 指标(分项,不用单一分)

1. **事实提取准确率** — 硬性条件/薪资/工时等字段识别是否正确
2. **证据支持率** — 每条结论能否指回原文
3. **红旗检出率 & 误报率** — 漏报危险和误伤正常公司同样是失败
4. **排序一致性** — /compare 排序 vs 人工排序(同档平局按命中计)
5. **建议可执行性** — 追问/行动是否可直接照做(人工评审)

## Persona 绑定

同一个 JD 对应届生、35+、转行者、急求职者的正确结论完全不同。标注时必须声明 persona;首发版保证 persona 内自洽,多人独立标注留待社区阶段。
